# SentinelGrid 0.2.1 — standalone fleet monitoring

Run the monitoring server, dashboard and notification delivery in a single Linux service. Install a small outbound agent on each monitored host. This release includes separate, statically linked server and agent packages for AMD64 and ARM64.

## What's new

- Customers see their own hosts. Administrators see the whole fleet. Each host has an independently revocable upload key.
- The agent reports CPU, memory, root disk usage, load, uptime, kernel release, network counters and listening ports. It checks configured TCP ports and buffers readings through connectivity outages.
- Set customer thresholds and per-host overrides in the dashboard. Preview which current alerts would change before saving. Detect sustained TCP failures, slow connections, flapping ports and projected disk exhaustion.
- Inspect recent listener changes, kernel changes and uptime drops alongside host measurements.
- Route incidents and recoveries to Gmail, Outlook, Telegram or a Microsoft Teams group chat. Teams can receive recurring healthy-fleet summaries. Each destination has an independent persistent retry queue.

## Install or upgrade

Choose the server archive for the monitoring server and the agent archive for each monitored host. Download SHA256SUMS, verify each selected archive against it, extract it and follow the included README.md. Run the installer from the extracted directory. For a public endpoint, configure HTTPS and create a customer login and one host key per agent. Notification setup and a credential-free example are included in the server archive.

Existing standalone preview users can back up the state directory and upgrade the server with the packaged installer. Preview agents can continue reporting. For users of the earlier Docker/PostgreSQL deployment, install the standalone server separately and enroll standalone agents. The legacy database, credentials and agent protocol are separate. Keep the previous installation and its backups available when migrating.

The server retains up to 120 samples per host. Forecasts use recent observations and change as workloads change. Linux 5.0.1 is a compatibility target. The standalone series has been exercised on Ubuntu kernel 6.8 and Linux 7.3, with additional ARM64 testing under emulation.
